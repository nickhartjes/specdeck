## Implementation notes

- **Unticked, need hardware or a release run:** 1.1 and 1.2 need a debug build on macOS (Claude's browser exists only there); this work was done on Linux, so the Open Questions in design.md are not filled in. 2.2 and 2.3 are implemented (`on_navigation` with `own_page` on session and settings windows, `web_page` on the browser window and in `navigate()`), but their hand checks in `just dev`, in release builds on each platform and by repeating 1.1 are not done. 7.2's checks pass (see below), but the hand run on macOS, Windows and Linux is not done.
- **App origin (decision 1):** Tauri has no public call for the address it serves the bundled page from, so `navigation::app_origin` takes the `devUrl` from `app.config()` in a development build and otherwise uses `tauri://localhost`, or `http://tauri.localhost` on Windows, which is what Tauri 2.12 uses without `useHttpsScheme`. If that setting is ever turned on, `app_origin` has to follow, or every window goes blank.
- **`navigate()`:** it uses `web_page`, except the empty start page, which a tool call has no reason to open. The tool's message is now "Only web addresses (http and https) can be opened."
- **3.1, generated files:** `permissions/autogenerated/` is git-ignored. `cargo build` writes it. `nix build .#specdeck` was not run to the end on this machine (see the worker report); crane builds in a writable copy of the source, so it is expected to work, but that is not verified.
- **3.2 and 3.3:** the test (`commands_are_listed_handled_and_granted` in `lib.rs`) was written with the capabilities and checked by removing an entry, which made it fail. Session windows get every command except the seven only the settings screen calls (`set_host_notifications`, `set_check_updates`, `set_screen_reader`, `set_verbose_logging`, `set_browser`, `set_screenshots`, `check_sharing_service`); the settings window gets the thirteen its screen calls. The hand run through the app in `just dev` is not done.
- **3.4:** done with Tauri's mock runtime (`browser::tests::grants`), which needs `tauri`'s `test` feature as a dev-dependency. The test builds the app's real context, so it checks the generated manifest and capabilities: `main` and `settings` may call `get_profile`, `browser-1` may not.
- **4.3, addresses kept:** react-markdown's default `urlTransform` empties `file:` and other addresses, which would hide them. `Markdown` keeps the address as written for `href` and drops only `javascript:`, `vbscript:` and `data:`, so a refused link's address still shows and can be copied. Nothing follows the `href`: a click always calls `preventDefault`, and the window's navigation rule refuses anything else anyway. A link with a scheme goes to the bridge, which refuses everything but web addresses, so `file:` links show "This link can't be opened." Links to a `#heading` or a relative path open nothing and say nothing.
- **4.4:** `Markdown` is the only renderer of anchors from session content. The two anchors left in `web/WebApp.tsx` are built from the page's own service and a join link the user typed, not from session content. Not changed, and not anchors: links the terminal detects (xterm's `WebLinksAddon`) use its default `window.open`, which the app's windows refuse; in the web viewer they open a new tab without an opener. Sending them through `openContentLink` would be a new feature, so it is a possible follow-up.
- **5.2:** the host's own name goes through the same filter when sharing starts (`Host::new`). If nothing is left, it shows as `Host`, which the app's name field (5.3) already prevents.
- **5.3:** `model/names.ts` filters the names in viewer events (participants, link and suggestion authors, shared files, braindump) where `ViewerScreen` receives them, and the name fields of the start screen, Settings and the web viewer.
- **5.5 and docs:** `guide/first-steps.md` is where names are described, so the note on hidden characters is there; `guide/follow.md` and `guide/host.md` do not describe names, so they are unchanged. `security/your-computer.md` mentions links, so it says that links in documents open in the browser too.
- **6.1:** a pending join link waits while the start screen asks for a name, and its question appears once a name is set. Joining from a link already failed without a name ("Set your name first."), so this is new behaviour, not a kept one.
- **7.2:** `just check` passes except one test: fmt, clippy, lint and type-check are clean, 775 Rust tests pass (including every new one), as do the 851 UI tests and the script tests. The one failure, `files_a_shell_command_changes_reach_the_timeline` in `crates/core/tests/host_session.rs`, also fails on the base commit (`be38c82`) on this machine, built in a separate target directory, so it predates this change. Under heavy machine load (load average about 40 on 12 cores) several UI tests hit vitest's 5-second timeout; with `--testTimeout=120000` all 851 pass. On this NixOS machine the check ran inside `nix develop .#specdeck` with rustup's toolchain first on `PATH`, because the shell's `rustc` (1.99.0) and rustup's `cargo-clippy` (1.99.1) do not mix. `just check-web` and the hand runs on each platform were not done.
- **After review:** content links carry an `href` only for web addresses; others are anchors without one (role `link`, focusable, the address as title), so a middle-click or "Open in new tab" can follow nothing else, and a middle-click goes through the same check. The name filter covers Unicode's Default_Ignorable_Code_Point and Bidi_Control (U+061C, U+00AD, the Hangul fillers and more), with `crates/protocol/tests/fixtures/shown-names.json` read by the Rust and the TypeScript tests. Windows are built only through `navigation::app_window` and `navigation::browser_window`, and `every_window_gets_a_navigation_rule` fails if a builder elsewhere, or one without `on_navigation`, appears (checked by removing the rule, and by building a window directly in `lib.rs`). Claude's browser also allows `about:srcdoc` frames. Unlike design decision 6, notification titles are escaped on Linux too, because dunst's default format renders markup in them.
